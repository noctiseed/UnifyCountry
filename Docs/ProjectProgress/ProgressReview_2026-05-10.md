# UnifyCountry 项目进度评估

评估日期：2026-05-10  
评估目标：按照成熟、可上线的肉鸽游戏产品标准，重新判断当前开发进展、完成度、主要风险与后续计划。

## 总体结论

当前项目已经具备一个较扎实的卡牌战斗原型，但距离成熟可上线的肉鸽产品仍处于早期阶段。

综合完成度评估：**约 22%**

更准确地说，当前项目状态是：

- 已完成：可玩的战斗原型、基础卡牌/单位/效果 CSV 驱动、连续关卡雏形、战后选牌奖励、主菜单、卡牌收藏页。
- 正在成型：战斗反馈、DOTween 动画、Buff 表现、卡牌图和单位图资源。
- 明显缺失：RunMap、随机事件、遗物、商店、休整、局外成长、存档、完整经济系统、发布流程、自动化测试、上线级音频与特效。

因此当前更接近“卡牌战斗垂直原型”，还不是完整肉鸽游戏。

## 模块完成度

| 模块 | 完成度 | 当前判断 |
|---|---:|---|
| 战斗核心规则 | 45% | 已有回合、布阵、抽弃牌、费用、波次、Buff、技能结算、胜负判断 |
| 局内卡牌构筑 | 30% | 有初始牌库和战后奖励，但奖励池、升级、删牌、流派构筑还浅 |
| 肉鸽 Run 循环 | 15% | 有连续 3 关雏形，但缺路线地图、事件、商店、遗物、休整 |

| UI 与交互 | 30% | 战斗 UI、主菜单、卡牌收藏页可用，但大量运行时代码生成，后期维护压力较高 |

## 当前已有基础

### 战斗系统

当前战斗系统已经具备以下能力：

- 准备阶段与正式回合。
- 初始手牌、抽牌堆、弃牌堆、每回合抽牌。
- 费用系统：准备阶段 5 点，正式回合恢复到 3 点。
- 3 排 x 5 列友方布阵。
- 敌方按行追加波次。
- 单位上阵、拖拽上阵、同行插入。
- 敌方先攻，友方反击。
- 死亡、补位、Boss 死亡胜利。
- 大本营生命与失败判断。
- 战斗日志。
- 战斗胜利后进入奖励选择。

## 主要问题与风险

### 1. 肉鸽结构尚未真正建立

当前连续关卡更像线性战斗挑战，缺少肉鸽核心：

- 路线选择。
- 地图节点。
- 随机事件。
- 遗物。
- 商店。
- 休整。
- 精英战。
- Boss 章节结构。
- 局内资源经济。
- 局外/局内状态边界。

如果继续只扩充战斗，很容易形成“战斗内容越来越多，但游戏循环仍然不成立”的问题。

### 2. 内容体量不足

成熟肉鸽通常需要足够的组合空间。当前内容量只够验证基础规则，不足以支撑长期重复游玩。

短期建议目标：

- 40-60 张可获得卡。
- 25-35 个遗物。
- 15-20 个事件。
- 8-12 场普通战斗。
- 3-5 场精英战。
- 1 个完整 Boss。

### 3. UI 架构需要逐步收敛

当前 UI 主要通过运行时代码生成，适合快速原型，但后续会影响：

- 美术调样式。
- 组件复用。
- 页面维护。
- 响应式适配。
- 动画与特效插入。

建议逐步迁移到 Prefab + Controller：

- `CardView.prefab`
- `UnitView.prefab`
- `BuffIcon.prefab`
- `BattlePage.prefab`
- `RunMapPage.prefab`
- `RewardPanel.prefab`

### 4. 战斗逻辑与 UI 耦合仍偏高

当前 `PrototypeBattleUi` 同时承担：

- 状态初始化。
- 回合推进。
- UI 构建。
- 动画播放。
- 奖励结算。
- 输入交互。

后续建议把核心规则逐步下沉到纯逻辑层：

- `BattleState`
- `BattleRunner`
- `BattleCommand`
- `BattleResult`
- `RewardService`
- `RunState`
- `RunController`

UI 只负责展示状态和提交玩家操作。

### 5. 缺少存档、测试和数据校验

上线前必须补齐：

- 当前 Run 存档。
- 设置存档。
- 卡牌/遗物解锁状态。
- CSV ID 校验。
- 效果类型校验。
- 波次引用校验。
- 基础战斗单元测试。
- 构建检查流程。

## 建议开发路线

### 阶段 1：完整 Run 垂直切片，预计 2-4 周

目标：做出一局 20-30 分钟可重复游玩的最小肉鸽闭环。

建议内容：

- 新增 RunMap 场景或页面。
- 支持节点路线选择。
- 节点类型：普通战斗、精英战、事件、商店、休整、Boss。
- 新增 RunState，保存当前牌组、金币、生命、遗物、地图节点、当前进度。
- 新增 10 个基础遗物。
- 新增 5 个事件。
- 战斗胜利奖励扩展为：选牌、金币、遗物、删牌、升级中的至少 2-3 类。
- 支持失败后重新开始完整 Run。

验收标准：

- 从主菜单开始新 Run。
- 进入地图。
- 选择节点。
- 打战斗。
- 领取奖励。
- 回到地图。
- 走到 Boss。
- 胜利或失败后回到结算。

### 阶段 2：核心乐趣验证，预计 4-6 周

目标：验证玩家是否愿意反复开局。

建议内容：

- 扩展到 1 个完整章节。
- 形成 4-5 个主要构筑流派：
  - 灼烧流。
  - 护甲/荆棘反伤流。
  - 英雄阵列流。
  - 过牌爆发流。
  - 低费铺场流。
- 新增精英战模板。
- 新增 Boss 机制。
- 新增卡牌升级或强化系统。
- 新增删牌与商店。
- 做第一轮数值平衡。

推荐内容目标：

- 40-60 张卡。
- 25-35 个遗物。
- 15-20 个事件。
- 3 个 Boss 或 Boss 形态。
- 10-15 个普通战斗模板。
- 3-5 个精英战模板。

### 阶段 3：产品化，预计 6-10 周

目标：从“能玩”提升到“像一个产品”。

建议内容：

- UI 迁移到 Prefab + Controller。
- 补齐设置菜单。
- 补齐存档系统。
- 补齐音效、BGM、战斗特效。
- 补齐教程与首局引导。
- 增加数据校验工具。
- 增加自动化测试。
- 增加构建流程。
- 优化不同分辨率适配。
- 优化战斗节奏与动画速度设置。

### 阶段 4：上线前打磨，预计 4-8 周

目标：达到可公开测试或小规模上线标准。

建议内容：

- 完整 QA。
- 崩溃与卡死修复。
- 存档兼容。
- 平衡性调整。
- 新手体验优化。
- Steam 页面素材。
- 成就系统。
- 本地化。
- 性能优化。
- Demo 版本切分。

## 下一步优先级

最高优先级：

1. 建立 RunState 和 RunMap。
2. 接入最小遗物系统。
3. 扩展战后奖励类型。
4. 接入当前 Run 存档。
5. 把地图到战斗再回地图的流程跑通。

中优先级：

1. 扩充卡牌和遗物内容。
2. 做事件系统。
3. 做商店和删牌。
4. 做精英战与 Boss 机制。
5. 做数据校验。

低优先级但必须规划：

1. UI Prefab 化。
2. 音频和 VFX。
3. 自动化测试。
4. 发布与构建流程。
5. 设置、本地化、成就。

## 下一次回顾建议

建议下一次回顾重点看以下指标：

- 是否已经能从主菜单完整跑完一局 Run。
- RunMap 是否有至少 5-8 个节点。
- 是否至少有 5 个遗物进入战斗结算。
- 战后奖励是否不再只有选牌。
- 是否有基础存档。
- 是否有 1 个 Boss 节点。
- 是否新增了数据校验或战斗规则测试。

如果这些完成，项目整体完成度可从当前约 22% 提升到约 35%-40%。
